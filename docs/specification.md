# Контракт 1.0 и политика KIB-02/1.0

JSON — объект с обязательными schema_version ("1.0"), network_name, zones, assets, access_rules. Зона содержит id (IT, DMZ или OT) и name. Состав зон произвольный, от одной до трёх. Устройство содержит id, name, zone, type. Правило содержит id, source, destination, protocol, port, action. Формат показан в examples. Дополнительные поля запрещены. Уникальность ID проверяется в каждой коллекции. Регистр значим. Для ID допустимы 1–40 латинских букв, цифр, точек, дефисов, подчёркиваний. ANY зарезервирован. Имена и типы — непустые строки до 120 символов без управляющих символов.

CSV — два файла UTF-8 assets.csv и rules.csv, в любом порядке, заголовки и порядок полей как в examples. Разделитель — запятая, кавычка внутри поля удваивается. Зоны выводятся из assets.zone. BOM и CRLF допустимы. Каждый файл до 1 МиБ, 1–200 устройств, 0–1000 правил. Ссылки должны существовать. JSON и CSV нормализуются одинаково. TCP, UDP, ANY — разрешённые протоколы. Порт — целое 0–65535, ANY или строка диапазона a-b (a<b). Любой диапазон шире одиночного сервиса. В CSV одиночный порт записывается десятичным числом. Допустимые действия allow и deny.

## Порядок решения

Ровно одна строка отчёта на allow, первое совпадение побеждает. deny учтены отдельно. Сначала сравниваются точные нормализованные записи с противоположным действием. Совпадение даёт REVIEW (C-01) для allow. Частичные пересечения и порядок ACL вне модели. Одинаковые условия с разными ID проверяются отдельно. Путь из двух разрешений не создаёт третьей строки.

1. P-06. ANY → конкретный PLC запрещено, критический уровень.
2. P-01. IT → любой конкретный PLC запрещено, критический уровень.
3. P-08. ANY в любом конце, протоколе или порте, а также диапазон портов запрещены, средний уровень.
4. P-03. PC-01 (IT, workstation) → JUMP-01 (DMZ, jump_server), только TCP/443.
5. P-04. JUMP-01 → ENG-01 (OT, engineering_station) TCP/3389 или HIST-01 (OT, historian) TCP/443. Для источника обязательны те же зона и тип, что в P-03.
6. P-05. HMI-01 (OT, hmi) или ENG-01 → PLC-01 (OT, plc), TCP/502.
7. P-02. Остальные межзонные соединения запрещены, высокий уровень.
8. P-07. Остальные внутрисегментные соединения требуют проверки.

Исключения P-03–05 требуют точного совпадения обоих ID, ролей, зон и сервиса. Импорт не может расширить политику. Незнакомый тип устройства допускается для инвентаризации и никогда не совпадает с разрешённой ролью. Неизвестный протокол, действие, зона или ссылка — ошибка входа. REVIEW не означает согласование.
