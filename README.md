# KIB-02 · Аудитор сегментации IT/OT-сетей

Учебное приложение для системного администратора небольшого производственного предприятия. По описанию сети проверяет, каким устройствам явно разрешено обращаться друг к другу и соответствует ли это политике KIB-02/1.0.

## Демонстрация

Выполните `npm run build` после установки зависимостей и откройте `dist/offline.html` в современном браузере. Если вы получили готовую однофайловую сборку, достаточно открыть её. В этом HTML уже есть React, стили, политика и оба примера. Установка, сервер и интернет для такого запуска не нужны. Для учебных файлов используется штатное окно выбора файлов.

1. На стартовом экране открыт «Учебный завод №1». У него 7 устройств, 3 сегмента и 9 разрешений. Сводка показывает 3 нарушения, 5 допустимых правил и 1 случай для проверки.
2. Нажмите R-01 в таблице. В карточке видны IT → OT, TCP/502, критический приоритет, пункт P-01, причина и рекомендация.
3. Включите «Нарушения» у схемы. Стрелка показывает направление одного исходного разрешения. Выберите ребро для подробностей. Фильтры под схемой и поиск относятся к таблице.
4. Нажмите «Выбрать демопример» и откройте «Без нарушений». Все 5 разрешений согласованы.
5. Нажмите «Загрузить конфигурацию». Выберите `examples/plant.json` или выделите вместе `examples/assets.csv` и `examples/rules.csv`. Анализ запускается после успешного чтения и валидации. При ошибке текущий отчёт сохраняется, а окно импорта остаётся открытым для повторной попытки.
6. «Экспорт отчёта» сохраняет полный JSON независимо от фильтра. Внутри есть сводка, версия политики, ID и исходные условия каждого разрешения, статус, зоны, основание и рекомендация. Явные запреты вынесены в excluded_denies.
7. Во вкладке «Устройства» есть инвентарь и исходные запреты. «Политика» показывает основания решений. «Журнал сессии» хранит последние 50 событий в памяти вкладки.

## Разработка и сборка

Выполните команды из корня репозитория.

Проверено на Node.js 24.22.3. Для установки зависимостей из npm нужен доступ к реестру пакетов. После установки проверка, сборка и запуск выполняются локально.

```bash
npm ci
npm test
npm run build
npm run dev
```

Откройте локальный адрес, который напечатает Vite (обычно http://127.0.0.1:5173). Ctrl+C завершает процесс разработки. Команда `npm run preview` показывает производственную сборку. Приложение хранит данные в памяти браузера. Сервер Vite используется только для разработки и раздачи файлов сборки.

## Как читать метрику

Каждый тест читает настоящий JSON-файл, проверяет его и запускает тот же модуль, который использует интерфейс. Для зачёта должны совпасть все ID, пункты политики и статусы, включая REVIEW. Для deny ожидается отсутствие строки разрешения. Лишняя строка, например выведенный многопереходный путь, провалит тест. Цель проекта: 18 из 20 конфигураций. Набор содержит 10 конфигураций с нарушением и 10 без нарушения. REVIEW учитывается отдельно от нарушения. Дополнительные проверки не входят в знаменатель. Команда `npm test` выводит результат и возвращает ненулевой код при расхождении. Для обновления подробного отчёта выполните `npm test -- --report`.

## Совместная разработка

`main` хранит принятые командой изменения. Начинайте задачу от актуального `main` в отдельной ветке и открывайте pull request. В описании перечислите изменения и способ проверки. Перед слиянием дождитесь проверки GitHub Actions и ревью участника команды.

## Ограничения

Аудитор принимает синтетические данные схемы 1.0 и сравнивает их с одной учебной политикой. Проверка касается только явно заявленных направлений. Маршрутизация, состояние сессий, NAT, порядок и частичное перекрытие ACL не моделируются. Наличие промежуточной зоны само по себе не создаёт сквозного разрешения. Незнакомые внутрисегментные сервисы требуют ручного решения. Поддерживается импорт однострочных CSV-полей. Экспорт предусмотрен в JSON. Доля верных ответов относится к фиксированному учебному набору.
